# Resumo 0223

**PASS no cenário integrado de outage PostgreSQL e worker.** O run E2E `5d8a2e6c-a506-470d-9ec7-157d358a49ab` usou `rotamoto_e2e`, um proxy TCP isolado e um processo worker com role PostgreSQL dedicada. Durante a falha, a API ficou viva (`/health/live` 200), readiness degradou para 503 e o endpoint de filas retornou erro sanitizado. Após restaurar o proxy, readiness e a fila voltaram; o comando permaneceu `unknown_outcome`, com uma tentativa, sem repetir o efeito. O evento inbox foi único; o pedido externo não gerou Delivery/Earning.

Causa-raiz: `pg-pool` emitia erro de cliente ocioso sem listener no pool, encerrando o Node. O listener sanitizado foi centralizado em `createPool`; também foi corrigida uma suposição de MFA no helper de sessão E2E. Restaurante `npm test` e `test-marketplace-worker-postgres.js` passaram. Restaurante commit local `1e66498`; Browser QA `5f9e384`, `d65751f`, `7f3c21e`; Motoboy sem alteração. Nenhum Browser visual/CDP foi executado. `workerAvailability` durável continua `unknown`, mas não bloqueou a prova do worker real neste cenário. Detalhes e artefatos em [REGISTROS/0223.md](../REGISTROS/0223.md).
