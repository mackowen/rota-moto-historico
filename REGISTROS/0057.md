## PASS

- Login autenticado Restaurante com MFA válido; MFA inválido rejeitado; sessão por cookie, CSRF estável, logout/login e acesso protegido ao vínculo Membership↔Driver. Mutação sem CSRF foi rejeitada pelo lifecycle. Tentativa de sobrescrever tenant por query foi rejeitada.
- Order criado por UI com double-submit sem duplicação, edição, Delivery correspondente e atribuição; Route criada/editada com duas `deliveryIds` ordenadas; relatórios/KPIs, Conta, navegação e eventos acessados.
- Entidades canônicas importadas foram reconciliadas por UUID entre instalações sem duplicar Order/Delivery. Pull autenticado Motoboy ficou limitado ao Driver da sessão; não houve confiança em `driverId` enviado pelo cliente.
- Ciclo cruzado canônico: Order → Delivery → atribuição → pull Motoboy → ACCEPTED → PICKED_UP → OUT_FOR_DELIVERY → ARRIVED → DELIVERED → reconciliação Restaurante. Earning canônico disponível após sync. FAILED e RETURNED também foram confirmados no PostgreSQL.
- Offline/retry via CDP: ACCEPTED persistiu localmente sem rede; sync falhou fechado enquanto offline; após reconexão, retry recebeu ACK canônico e reconciliou.
- APIs autenticadas responderam `no-store` e não foram armazenadas pelo service worker/Cache Storage. Inspeção de localStorage/IndexedDB não encontrou senha, token, CSRF, MFA ou Authorization. Runtime não leu o migration ledger.
- Oito combinações app/viewport em 360×800, 393×873, 768×1024 e 1366×768 não tiveram overflow horizontal. Sem exceções JS ou erros de console. Fallback manual de câmera e prova de assinatura local funcionaram.
- Guardas/paridade/lifecycle E2E passaram. `npm test` nos dois apps, `npm run test:e2e-guards`, `npm run test:e2e-lifecycle`, `node --check` dos arquivos alterados e `git diff --check` passaram.
- Fingerprint SHA-256 do catálogo/ledger read-only de `rotamoto` antes/depois: `0ce3aa0ae64db6398f54840d0894917c249cd76a0581b2f7f8e64aecd46303c9`, idêntico. Todas as conexões do harness Browser foram explicitamente para `rotamoto_e2e`; lifecycle confirmou rollback sem resíduo.

## FIXED

- Corrigido o reenvio de entidades canônicas importadas como operações “locais” de uma instalação nova: Order/Delivery/Driver/Route só entram no push quando locais/alterados. Um `deliveryId` derivado para Order importado é efêmero até uma edição local.
- Sync agora resolve UUID canônico sob o tenant e tipo de entidade e cria alias da nova instalação para o mesmo registro. Atualizações carregam `baseVersion` da última `canonicalVersion`; o servidor remove metadados de revisão do payload persistido. A regressão foi coberta dentro do lifecycle rollback-scoped e no browser.
- Corrigidas condições internas reproduzíveis de CSRF concorrente/sessão, transação multi-store e submit de Route sombreado por variável global `event`; corrigido no Motoboy o bloqueio de ação enquanto recálculo de rota assíncrono terminava. Contrato de sync atualizado nos dois `CONTRACT.md`.
- O timeout de RETURNED da primeira tentativa foi tratado como condição de espera do harness: as repetições observaram estado canônico e evento reconciliado. Não foi necessário enfraquecer validação ou alterar autorização para passar.
