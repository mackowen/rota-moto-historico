# Campanha 0171 — infraestrutura Browser E2E autenticada

**Resultado: PASS para o gate obrigatório de infraestrutura autenticada.** O teste demonstrou login via formulários reais nos dois aplicativos, chamadas autorizadas, sessão e instalação persistidas em PostgreSQL E2E e leitura do mesmo Driver canônico nos dois clientes. Não criou Order, Delivery ou Route. Isso habilita a tentativa de 0172; não atesta o ciclo operacional completo.

## Ambiente e preparação

- PostgreSQL de escrita: exclusivamente `rotamoto_e2e`; runner exige `NODE_ENV=test`, URLs loopback fixas para `rotamoto_e2e`, ausência de `DATABASE_URL`/`MIGRATOR_DATABASE_URL` e guarda de fixtures.
- Backend: `server.js` real do Restaurante em `127.0.0.1`, modo de teste, conectado à role runtime E2E. Os servidores estáticos Browser encaminham `/api` ao runtime. Nenhum handler de autenticação paralelo foi usado.
- Identidades: tenant/empresa, Owner sintético, Driver sintético e usuário de equipe com role restrita; sessão autenticada em cada perfil Chromium separado. A preparação foi feita pelo lifecycle E2E existente e por rotas administrativas autenticadas. Senha/token de convite ficaram apenas em memória e não foram registrados.
- RLS, CSRF, RBAC e autenticação não foram desativados. O usuário E2E tinha permissões de pedidos/sync e vínculo explícito ao Driver.

## Evidência reproduzível

Runner local: `browser-tests/campaign-0171-authenticated-runtime.cjs`.

Comando (URLs de conexão sem senha):

```sh
NODE_ENV=test ROTAMOTO_E2E_CAMPAIGN=0171 \
E2E_RUNTIME_DATABASE_URL=postgresql://rotamoto_app@127.0.0.1:5432/rotamoto_e2e \
E2E_MIGRATOR_DATABASE_URL=postgresql://rotamoto_migrator@127.0.0.1:5432/rotamoto_e2e \
node campaign-0171-authenticated-runtime.cjs
```

Resultado final: `PASS`; fixture retida `13b84f48-79ae-4d4f-a5cc-fa2adb8025a4`; evidências locais em `browser-tests/evidencias/campanhas/0171/0939f74d-477b-4ef2-a2d8-b0d56db712fd` (modo restrito). Dois logins autenticados, duas leituras autorizadas de Driver e mesmo ID canônico, um registro Driver no domínio, sessões PostgreSQL persistidas e instalações sync para `restaurante` e `motoboy`. Zero Order/Delivery/Route pré-semeados. Sem erros JavaScript. As respostas 401 iniciais de leitura de sessão precedem login e são esperadas; não houve outras respostas de erro HTTP no ensaio aprovado.

Uma primeira tentativa usando os handlers de fixture em vez do runtime real retornou 404 para uma requisição secundária do Motoboy. O harness foi corrigido para iniciar o `server.js` normal em modo test; a execução final acima passou. A primeira execução e seus artefatos permanecem retidos para rastreabilidade, sem limpeza.
