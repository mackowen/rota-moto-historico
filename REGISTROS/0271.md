# REGISTRO 0271 — Correção funcional de configurações do Motoboy

**Resultado da campanha: PARTIAL.** Foram exercitados e corrigidos três caminhos de gravação com falha reproduzível: Aparência/tema, autosave de ajustes (`minFee`) e meta diária do Driver. Isso não fecha a matriz de todas as configurações, RM-AUD19-02/10 ou RM-D1-SETTINGS-SAVE.

## Preparação e escopo

Preservadas as tags de baseline Restaurante `v5.50-ui-mobile-fix5` e Motoboy `v39.6-ui-mobile-fix2`. O código foi alterado somente no Motoboy, em branch própria `codex/campaign-0271-motoboy-settings-fixes`. Restaurante não recebeu alterações. `browser-tests` não foi modificado; o runner CDP foi temporário em `/data/data/com.termux/files/usr/tmp`.

Não houve escrita no banco oficial, mudança de Company/Driver ownership, MFA, papéis, integração externa ou serviço permanente. Browser usou identidade sintética autenticada, `rotamoto_e2e` pela fixture transacional e IndexedDB descartável do perfil Chromium temporário.

Portanto os PASS são de escopo dos fluxos atuais e não de encerramento global.

- `npm test` no Motoboy: **PASS**, exit 0; inclui ownership Company/Driver, persistência da meta diária, sync, navegação, identidade e regressões existentes.
- Focados: `node tests/test-driver-owned-goal-persistence.js`, `node tests/test-configuration-ownership.js`, `node --check app.js`, `git diff --check`: **PASS**.

Proteção `beforeunload` ativa com rascunho e liberada após salvar. 360/390/768px × claro/escuro: seis combinações sem overflow. Zero exceções JavaScript e zero HTTP 5xx no relatório final.

- Runtime: API E2E runit voltou a `run`; `/health/ready` indicou API e PostgreSQL prontos. O lifecycle fixture terminou por rollback transacional. O executor não publicou contagens independentes de resíduos nesta campanha; nenhum teste habilitou commit/fixture retida.
