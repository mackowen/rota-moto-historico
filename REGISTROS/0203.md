# Campanha 0203 — Recuperação transacional completa

Data: 2026-10-15  
Resultado: **PASS no cenário de falha testado**.

## Causa-raiz e correções

O primeiro Browser outage run interrompeu sockets de clientes PostgreSQL do runtime enquanto estavam emprestados pelo pool. `pg-pool` remove o listener destinado a clientes ociosos no período de checkout; a conexão emitia `error` sem handler e o processo Node encerrava. `backend/postgres/connection.js` agora mantém listener de contenção por cliente conectado; a query/transaction em andamento continua recebendo falha e o runtime não termina.

Durante a mesma repetição foi reproduzida uma exceção MapLibre após navegação/reautenticação: callback de `requestAnimationFrame` do adaptador Leaflet consultava `_map.getZoom()` depois de a camada ter sido removida. O build `scripts/build-map-runtime.js` aplica guard para `_map` e `_glMap` antes do callback, e `tests/test-map-runtime-lifecycle.js` fixa a regressão. A asserção de sessões do runner também foi corrigida: logout/relogin pode revogar a sessão anterior, então o aceite exige ao menos uma sessão ativa atual, não duas sessões simultaneamente ativas.
