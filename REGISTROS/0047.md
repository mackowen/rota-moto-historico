## Runtime, HTTP e segurança

- Criados `backend/runtime/config.js`, `secret-provider.js` e `lifecycle.js`.
- `NODE_ENV` aceita development/test/production; valor ausente mantém default somente para development; valor vazio/inválido falha. Production exige HOST loopback, PORT, DATABASE_URL explícita para banco `rotamoto` e usuário `rotamoto_app` sem senha na URL, TLS `sslmode=verify-full`, CA externa, módulo absoluto de secret provider fora do repositório, origens HTTPS exatas, Host allowlist e IPs exatos de proxy confiável. Rejeita `MIGRATOR_DATABASE_URL`, hosts DB loopback, parâmetro/fragmento de URL inesperado e proxy não allowlisted. O provider entrega password ao `pg` apenas em memória; nenhum provider real ou segredo foi criado.
- Forwarded client IP só é aceito quando o peer de socket é exatamente um IP em `TRUSTED_PROXY_ADDRESSES` e o header contém um único IP válido. Os handlers de identity/admin/domain/sync usam o endereço resolvido; sem proxy configurado usam o peer. `X-Forwarded-Proto` nunca influencia segurança. O backend mantém bind loopback e valida Host.
- Respostas HTTP incluem CSP `default-src 'none'`, nosniff, frame denial e no-referrer; HSTS só em produção (o exemplo nginx oculta duplicatas e adiciona no TLS edge). CORS usa origens exatas. Cookies de sessão continuam `__Host-`, Secure, HttpOnly, SameSite=Lax. Content limits existentes (identity/admin 16 KiB, sync 1 MiB) foram preservados; Node limita cabeçalhos 16 KiB/100, request 30s, headers 10s, keepalive 5s; pool usa max 5, conexão 1.5s, statement 5s e idle 10s.
- Readiness verifica conexão como `rotamoto_app`, `domain_records`, `sync_installations`, `sessions.mfa_verified_at` e `memberships.driver_id`. Startup recusa role/schema incompatível e não executa migration. Bootstrap errors são sanitizados. Logs JSON registram request ID, método/path, duração, status/código estável e eventos de ciclo, sem body, token, credenciais ou PII. Pool error inclui só código sanitizado.
- SIGTERM/SIGINT deixam de aceitar conexões, fecham idle, drenam requests até 10s, forçam fechamento no timeout e encerram pool; falha de encerramento resulta exit code 1. Workers continuam sem lifecycle próprio pois não existem workers ativos.
- `.env.example` foi reduzido a configuração de desenvolvimento e removidas variáveis/endpoints/segredos-placeholder de iFood/99Food/Keeta. `.node-version` fixa Node 26.4.0, runtime usado para esta validação local; engines existentes `>=18` permanecem. Node/Termux local não é qualificação de produção.
- O rate limit em memória continua por processo; o exemplo nginx acrescenta limite por IP. Alta disponibilidade ainda exige rate limit compartilhado/distribuído.
