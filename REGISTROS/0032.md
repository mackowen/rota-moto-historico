## Inventário read-only

- `rotamoto_app` é owner do database `rotamoto`, do schema `rotamoto` e das 18 tabelas, incluindo `schema_migrations`. ACL explícita do database/schema/tabelas é nula; ownership concede DDL. Database owner também obtém CREATE em `public` via `pg_database_owner`.
- O schema contém duas funções (`current_tenant_id`, `guard_audit_log_immutable`), um trigger append-only em `audit_log`, nenhuma sequence, nenhuma view/materialized view, nenhum tipo independente, operador/collation/conversion ou objeto de text search owned pela aplicação. Índices e TOAST acompanham as tabelas. Extension `plpgsql` pertence a `u0_a436`; zero large objects pertencem ao app.
- Não existem default privileges personalizados. Dez tabelas tenant têm RLS e `FORCE`, com dez policies `tenant_isolation`. Os únicos logins observados foram `rotamoto_app` e `u0_a436`; não há membership envolvendo o runtime.
- `u0_a436` aparece nos catálogos como superuser existente. A senha não foi lida, solicitada, armazenada ou utilizada; nenhuma entrada foi adicionada ao `.pgpass`.
- API usa explicitamente `rotamoto_app`. O migration runner aceita `DATABASE_URL` por processo separado. O script de teste PostgreSQL atual compartilha uma URL para DDL de teste, RLS runtime e fixtures; por isso ainda exige adaptação antes de validar a fronteira com duas roles.

## Artefatos preparados

- Restaurante: `backend/postgres/admin/role-split.sql` cria/configura `rotamoto_migrator` sem senha, sem SUPERUSER/CREATEDB/CREATEROLE/BYPASSRLS, mantém database sob `u0_a436`, transfere schema/tabelas/sequences/routines/tipos suportados do schema para migrator, restringe o runtime a CONNECT/USAGE e DML efetivamente usado pela API, revoga acesso ao ledger, preserva RLS/FORCE e define defaults fail-closed para objetos futuros.
- O script exige confirmação psql de checkpoint, faz preflight da sessão/database/owners/logins/memberships/RLS, usa `lock_timeout`, transação para ownership/grants de objetos e postconditions. `ALTER DATABASE OWNER` fica fora da transação por restrição do PostgreSQL; possível efeito parcial está documentado.
- `backend/postgres/admin/role-split-runbook.md` documenta checkpoint completo manual, janela de manutenção, comando exato, `\\password rotamoto_migrator`, validações pós-execução e limites/procedimento de rollback.
