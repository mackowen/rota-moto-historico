## Solicitação

O proprietário informou que o bootstrap inicial pretendido é pela página servida em `8083`, ligada à API E2E e ao banco `rotamoto_e2e`, e pediu também corrigir a mensagem/opção que permite copiar o comando na página.

## Análise e causa

A interface do assistente era compartilhada entre oficial e E2E, mas mostrava e copiava sempre `npm run bootstrap:prepare-browser`, comando estritamente limitado ao banco oficial `rotamoto`. O endpoint público de status não identificava o alvo. A API E2E também mantinha o modo local-only desativado; não havia emissor de autorização web E2E compatível com o bootstrap local.

## Correções

- A API expõe `target` sanitizado (`official`/`e2e`) derivado da configuração real, sem incluir segredos.
- O E2E é habilitado estritamente para `NODE_ENV=test`, banco `rotamoto_e2e`, campanha `0243` e origem/peer loopback. O fluxo oficial mantém sua guarda própria.
- A página em 8083 identifica claramente `rotamoto_e2e`, exibe e copia `npm run bootstrap:prepare-browser:e2e`, explica que não acessa o oficial e apresenta o modo E2E local-only. O assistente geral de provisionamento não é oferecido nesse alvo.
- Foi criado emissor CLI E2E com confirmações explícitas de ambiente/banco, validação do keystore E2E, identidade da conexão, readiness, autorização de uso único por dez minutos e auditoria local privada. O caminho não envia convite por email.
- Documentação operacional diferencia página oficial 8081 e E2E 8083.
