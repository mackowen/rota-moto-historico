## Backup: análise do HTTP 404

A campanha 0294 observou `GET /api/admin/backup` 404 durante execução no harness transacional. Nesta campanha rastreei `app.js`, `server.js` e `backend/admin/backup-http.js`: a UI constrói exatamente `/api/admin/backup`; o servidor registra o handler e reconhece o GET de status. Com store ausente o servidor atual retorna 503 `BACKUP_ADMIN_NOT_CONFIGURED`. O host `runFixtureLifecycle` não registra handler de Backup e seu fallback para rotas não reconhecidas é 404. Portanto o 404 veio do harness sem handler, não de rota ausente nem URL errada. O runtime atual confirma 503 de capacidade/configuração. Nenhum endpoint paralelo foi adicionado. Sem write, restore, destino ou segredo real. Evidência: [investigação de rota](EVIDENCIAS/0295/backup-route-investigation.md).
