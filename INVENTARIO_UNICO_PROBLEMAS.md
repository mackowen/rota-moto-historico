# Inventário único de problemas RotaMoto

**Revisão:** 2026-10-19 · Inventário cumulativo; campanha 0256-D4 · **Autoridade de estado:** evidência do registro mais recente por item. Este inventário não muda estado por inferência, campanha concluída ou sucesso isolado de `npm test`.

## Como usar

Este documento é o índice operacional único. IDs e linhas históricas existentes são preservados; quando dois registros descrevem a mesma capacidade, a linha principal lista os IDs predecessores como aliases/rastreabilidade, sem apagar os registros-fonte. `PENDENCIAS.md` continua sendo o arquivo de arquivo histórico integral, incluindo itens antigos que não foram revalidados nesta reconciliação. Itens desses registros sem prova atual são mantidos abertos, não convertidos em PASS. Novos documentos de campanha devem atualizar este inventário com estado, evidência e critério de aceite.

Estados: `OPEN` = trabalho não concluído; `PARTIAL` = evidência/capacidade parcial; `BLOCKED_*` = depende de decisão, permissão, infraestrutura ou agente externo; `PENDING_OWNER` = ação física/decisão do proprietário; `PASS_SCOPE` = só a parte local declarada passou, com regressão obrigatória; `PASS` = aceite específico comprovado, nunca PASS geral do produto.

## Regra obrigatória de encerramento

1. Toda campanha compara os IDs deste arquivo antes/depois e registra explicitamente `resolvidos` (com artefato/evidência e aceite), `remanescentes`, `bloqueados`, `regressões` e `não exercitados`.
2. Um item só muda para PASS quando passa seu critério específico com evidência reproduzível: teste/HTTP/DB/CDP adequado, dados sintéticos e rollback quando houver mutação. `npm test` é gate de regressão e nunca prova, sozinho, persistência, segurança, UX ou operação.
3. Regressão não reabre automaticamente requisito distinto; deve apontar ID atingido e atualizar estado/evidência. Um PASS local pode permanecer `PASS_SCOPE` enquanto físico/external permanece aberto.
4. Quando o aceite envolve Chrome Android, teclado, impressão, GPS/câmera ou suspensão real, CDP não fecha o item: adicionar `PENDING_OWNER` e a evidência física sanitizada fornecida pelo proprietário.
5. Não alterar banco oficial, privilégio, MFA, credencial ou integração real como meio de obter evidência sem autorização e gate explícitos.
